## 1. 「AIが作った感」の原因（全体方針）

スクリーンショット（`Builds/Verification/`）とコードを見て、共通する原因は次の5つ。個別項目はすべてこのどれかを解消するためのもの。

1. **全部UIで完結する**: 茹で・湯切り・仕上げが右パネルのゲージとボタンだけで済み、3Dの鍋や器を見なくても遊べる（`05-cooking-boil.png`）。→ 3Dの手がかり（湯気・泡・色・音）を主にし、UIは補助にする。
2. **均一・左右対称・繰り返し**: 街の建物が同じファサードの色違い（`25-winter-street.png`）、スープの油玉が同じ大きさの円のドット柄（`07-cooking-result.png`）、床のジグザグ模様（`08b-eating-closeup.png`）。→ ばらつき・崩し・経年感を足す。
3. **答えが画面に書いてある**: 客が「ピリ辛（辛さ1）」と数値で言い、注文欄の下に「具材：…」が全文出る（`03b-register-order.png`）。→ 解釈する余地を作る。
4. **キャラに感情の動きが少ない**: 待つ・食べる・喜ぶがほぼ同じポーズで、フィードバックは文字の吹き出しとトースト。→ 体の動きと表情で伝える。
5. **UIが汎用テンプレート**: どの画面も同じ角丸クリーム色パネル＋緑/赤ボタン、汎用アイコン。→ 店のテーマ（伝票・木札・黒板・帳簿）に寄せる。

## 2. セキュリティ・堅牢性（P0）

オフラインの単独プレイゲームのため外部からの攻撃面は小さい。主なリスクは「保存ファイルの破損・改ざんによる起動不能や表示崩れ」。

### S1. 読み込み時の例外の取りこぼしで起動不能になる【P0】
- 現状: `Core/SaveRepository.cs` の `Load()` は `IOException / ArgumentException / InvalidOperationException` しか捕まえない。`SaveMigration.Migrate`・`Normalize`・`Validate` 内で `NullReferenceException`・`IndexOutOfRangeException`・`KeyNotFoundException`・`FormatException`・`OverflowException` などが出るとバックアップに切り替わらず、起動時に例外で止まる。
- 対応:
  - `Read()` の呼び出しで、致命的でない例外（`OutOfMemoryException` などを除く）をすべて捕まえ、`.bak` へフォールバックする。
  - 主・バックアップとも読めない場合は、壊れたファイルを `malatang-save.corrupt-<日時>.json` に退避してから新規開始し、タイトル画面でその旨を表示する（黙って上書きしない）。
- 完了条件: 欠けたフィールド・型違い・null 要素・巨大な数値などを含むファジング的な EditMode テスト（20ケース以上）で、例外が外に出ず「バックアップ復旧」か「退避して新規」のどちらかになる。

### S2. 読み込み時の値の範囲検証が足りない【P0】
- 現状: `Validate` は所持金 `moneyFen`、経験値の上限、家具の `x / z / rotation` の範囲、注文・常連・履歴などのリスト件数、文字列の長さを検証していない。改ざんや破損で極端な値が入ると、描画・計算・UIが崩れる。
- 対応: 範囲外は拒否ではなく**クランプまたは除去して正規化**する（`Normalize` に寄せる）。例:
  - `moneyFen` は `[-10^9, 10^12]`、`experience` は `[0, 上限]`
  - 家具はグリッド外・未知の回転値を除去
  - `orders` は上限件数（例: 200）、`history` は直近 N 日、`recentReviews` などは上限で切り詰め
  - 文字列（`storeName`・客名・レビュー）は長さ上限と制御文字の除去
- 完了条件: 各項目の境界値テスト。正規化後に `Validate` が通る。

### S3. 店名のリッチテキスト注入・サロゲートペアの分断【P0】
- 現状:
  - 店名は 3D 看板の `TextMesh`（`Presentation/World/StoreBuilder.cs` の `Label`）に表示される。`TextMesh.richText` は既定で有効なので、`<size=300>` や `<color=…>` を含む店名で看板が崩れる。入力欄経由でも保存改ざんでも起こる。
  - `RestaurantSimulation.RenameStore` の `Substring(0, 16)` は UTF-16 単位で切るため、絵文字などのサロゲートペアを分断して不正な文字列になり得る。読み込み時は長さを検証していない。
- 対応:
  - ユーザー由来の文字列を表示するすべての `TextMesh` / `Text` で `richText = false`（`supportRichText = false`）にする。または表示前に `<` `>` をエスケープする共通関数を作る。
  - 切り詰めは `StringInfo`（書記素単位）で行い、改行・制御文字・ゼロ幅文字を除去する。同じ関数を読み込み時の正規化にも使う。
- 完了条件: タグ・絵文字・結合文字・改行を含む店名の EditMode テスト。看板が崩れないことをスモークのスクリーンショットで確認。

### S4. 保存ファイルのサイズ上限がない【P0】
- 現状: `File.ReadAllText` で丸ごと読む。巨大なファイルがあるとメモリを使い切る。
- 対応: 読む前に `FileInfo.Length` を確認し、上限（例: 8 MiB）を超えたら破損扱い（S1 の退避フローへ）。
- 完了条件: 上限超えファイルのテスト。

### S5. バックアップ作成が原子的でない【P1】
- 現状: `Save()` の `File.Copy(path, path + ".bak", true)` は途中で落ちると `.bak` が壊れる（主ファイルは無事でも、次の破損時に頼れない）。
- 対応: `.bak.tmp` へコピーしてから `File.Replace` / `File.Move` で置き換える。
- 完了条件: コピー途中の失敗を模したテスト（`.bak.tmp` が残っても次回の読み込みに影響しない）。

### S6. チェックサムが改ざん防止ではないことを明記する【P3・情報】
- 現状: キーなしの SHA-256 なので、誰でも再計算して改ざんできる。オフラインの単独ゲームなので**現状は問題ない**（チートは本人の自由）。
- 対応: `SaveRepository` の Docstring と DESIGN.md に「破損検知用で、改ざん防止ではない」と明記する。将来ランキングやオンライン要素を入れる場合は、サーバー側検証が必要であることを書いておく（クライアント内の鍵による HMAC では防げない）。

### S7. 配布ビルドの取り扱い【P1】
- 現状: README の「起動」が開発ビルド `Builds/Mac/Malatang Story.app` を案内している。開発ビルドでは `--malatang-smoke <path>` や `MALATANG_SMOKE_OUTPUT` で任意のパスにスクリーンショットと保存データを書き出せる（`GameApplication.cs`）。リリースビルドでは `#if UNITY_EDITOR || DEVELOPMENT_BUILD` で無効化済みで、これは正しい。
- 対応:
  - README で、人に渡すのはリリースビルド（`Build Mac (Release)`）だけと明記する。
  - スモーク出力先は、存在するディレクトリであることを確認し、`..` を含むパスは拒否する（開発用でも誤操作対策として）。
  - リリースビルドで `Debug.Log` の詳細（`[SoupPrewarm]` のメモリ量など）を出さない。
- 完了条件: リリースビルドでスモーク引数が無視されることを確認して報告する。

### S8. その他の確認事項【P3】
- リポジトリ直下の `submit_M805_20261018.zip` は `.gitignore`（`*.zip`）で追跡外になっていることを確認済み。今後も秘密情報やビルド成果物をコミットしないよう、`git ls-files` で確認する手順を README の開発節に追記する。
- iOS の保存先は `persistentDataPath`（Documents）。iCloud バックアップに含まれるのは仕様どおりでよいが、`UIFileSharingEnabled` を有効にしないこと（Finder から保存データを書き換えられるため）を DESIGN.md に記録する。

## 3. キャラの操作性・当たり判定

### A1. 移動に加速・減速がなく硬い【P1】
- 現状: `RestaurantWorld.HandleInput` は `playerAgent.Move(delta * speed * dt)` で、入力がそのまま速度になる。止まる・曲がるが瞬時で、ちびキャラの重さが感じられない。
- 対応: 速度を内部に持ち、加速（約0.12秒で最高速）と減速（約0.08秒）を補間する。急な方向転換時は一瞬減速し、体を傾ける（`CharacterRig` に傾きを追加）。スティックの倒し量で歩き／小走りを変える。Shift（Mac）・スティックを最大まで倒す（iPhone）で小走り（速度1.35倍、足音を速く）。
- 完了条件: 速度補間の EditMode テスト（純粋関数に切り出す）。操作の録画 GIF か連続スクリーンショット。

### A2. 「今どれを操作するか」が分からない【P1】
- 現状: `NearestStation` は 1.7m 以内の最寄りを選ぶだけで、向きを考慮しない。どの設備が対象かが画面に出ない。
- 対応:
  - 候補の評価を「距離＋向いている方向（前方60度を優先）」にする。
  - 対象設備をアウトライン（または縁の発光）で強調し、頭上に「E 厨房」「E レジ」などのキー表示を出す（iPhone では右下の丸ボタンのアイコンを対象に合わせて変える）。
- 完了条件: 2つの設備の中間に立ったとき、向いている方が選ばれるテスト。

### A3. お客さんに当たり判定がなく、タップできない【P1】
- 現状: コライダー付きの `WorldTarget` は設備とテーブルだけ。客はタップしても反応しない。また客とプレイヤーの回避は `LowQualityObstacleAvoidance`・半径0.24で、通路で押し合って詰まることがある。
- 対応:
  - 客にカプセルの当たり判定（トリガー用の別レイヤー）を付け、タップで「その客の注文票を選ぶ」「直前のせりふを再表示する」。
  - プレイヤーの `avoidancePriority` を客より高くし、プレイヤーが客に押し戻されないようにする。客は道を譲る（少し脇に避けてから戻る）。
- 完了条件: 狭い通路で客とすれ違う PlayMode テスト（一定時間内に通過できる）。

### A4. 一人称の照準判定が遮られる・手が画面を塞ぐ【P1】
- 現状:
  - `UpdateLookTarget` は `Physics.Raycast` で最初に当たったものを見るため、手前のテーブルや装飾に遮られて設備を選べない。
  - `17-first-person.png` では右下の手（白い大きなミトン状）が画面の約1/6を塞いでいる。
- 対応:
  - 操作対象専用のレイヤーマスクを作り、`SphereCast`（半径0.15程度）で判定する。照準が対象に合ったら照準を拡大し、名前を表示する。
  - 一人称の手は縮小して画面端へ寄せ、歩行に合わせて小さく揺らす（ヘッドボブは設定でオフにできるように）。
- 完了条件: 対象の手前に装飾がある配置で選べる PlayMode テスト。

### A5. タップ移動のフィードバックがない【P1】
- 現状: `WalkTo` は行けない場所なら `false` を返すだけで、画面に何も出ない。行ける場所でも目的地が表示されない。
- 対応: 目的地に小さな輪のマーカー（着いたら消える）を出す。行けない場所は×印を一瞬出して小さな音を鳴らす。

### A6. 遠くの設備を押すと瞬時に操作される【P2】
- 現状: `Visit` は経路が見つからないと、その場で `action()` を実行する。歩かずに遠隔操作になり、空間の手触りがなくなる。
- 対応: 経路がない場合は「近づけません」と表示する。例外は調理・レジのモード切り替え（カメラ移動でつなぐ）だけにする。

### A7. キー割り当ての衝突【P1】
- 現状: README の表で「カメラ回転 Q / R」と「内装の回転 R」が同じキー。
- 対応: 内装中はカメラ回転を無効にするか、内装の回転を `T` などに分ける。キー割り当ての一覧をヘルプ画面に出し、設定で変更できるようにする（P3）。

### A8. 小さな改善【P2】
- `OverUI()` が呼ばれるたびに `List<RaycastResult>` と `PointerEventData` を新しく作っている → フィールドに持って使い回す（GC削減）。
- 見下ろしカメラの回転を、離したときに 45 度単位へゆっくり吸着させるオプション。
- ゲームパッド対応（Input System の既存アクションに追加）【P3】。
- 左利きモード（移動スティックを右下へ）【P3】。

## 4. 作業している感（調理の手触り）

### B1. 3Dの手がかりを主役にする（茹で）【P1】
- 現状: `05-cooking-boil.png` のとおり、茹で加減は右パネルのゲージで判断する。網じゃくの中の具材は小さく、湯気・泡・音の変化がほとんどない。
- 対応:
  - 鍋ごとに、沸騰の泡（パーティクル）・湯気の量・ぐつぐつ音の強さを、具材の茹で上がり具合に連動させる。
  - 具材の色・艶を茹で進行に合わせて連続的に変える（既存の生／茹での2状態の間を補間）。食べごろの具材は小さく光る。煮えすぎはしんなり縮み、色がくすむ。
  - カメラを網じゃくに少し寄せ、具材が見える大きさにする。
  - 設定の「ゲージ表示」を「常に／簡易／なし（上級）」で選べるようにし、「なし」で高評価なら追加の経験値。
- 完了条件: 茹で進行と見た目パラメーター（色の補間率・泡の量）の対応を純粋関数にしてテストする。スモークで茹で途中の寄り写真を追加する。

### B2. ボタン一つで終わるショートカットが手触りを消している【P1】
- 現状: 「残りをすべて入れる」「振る」「秤で量る」などのボタンで各工程が終わる。
- 対応: ボタンは残す（アクセシビリティのため）が、3D操作をしたときだけ小さなボーナス（湯切りのリズム成功で+1など）や演出が出るようにして、3D操作を選ぶ理由を作る。ボタン使用時の評価は変えない（下げない）。

### B3. 具材を取る【P1】
- 現状: 具材をタップすると物理で器に落ちる。トングや手がなく、「取っている」感じが弱い。
- 対応: タップ位置からトングが出て具材をつまみ、器の上で離すアニメーション（0.3秒程度、連打時は短縮）。量が多い具材（もやし等）は長押しで「ひとつかみ追加」。器に落ちたときに小さく弾み、汁気のある具材は器が少し揺れる。

### B4. 湯切りにリズムを【P1】
- 現状: 上下ドラッグまたは「振る」ボタン。3〜4回がベスト。
- 対応: 振るたびに水しぶき（パーティクル）と「シャッ」の音。テンポよく振る（0.25〜0.5秒間隔）と音の高さが上がり、最後に「ピタッ」と止める演出。回数表示は網じゃくの横に小さく。

### B5. 仕上げの手触り【P1】
- 現状: 長押しでスープを注ぐ。ラー油・薬味は瓶をタップ。
- 対応:
  - 注ぐ間、液面が上がり、注ぎ口から液体の筋（ライン描画）が出る。目標の液面に線を出し、注ぎすぎるとあふれ演出（品質は既存ルールのまま）。
  - ラー油はドラッグした位置に輪を描くように垂れる。薬味は器の上をなぞった軌跡に散る。

### B6. 完成の瞬間を気持ちよく【P1】
- 現状: 完成カードに点数が出るだけ（`07-cooking-result.png`）。
- 対応: 器の上に湯気が立ち、カメラが少し寄る → 点数が0からカウントアップ → 80点以上で「お見事」系のスタンプが押される演出と音。隠しレシピ・相性・希少は順番に1つずつバッジで出す（一度に全部出さない）。

### B7. 複数の鍋を並行して回す楽しさ【P2】
- 現状: 店内画面では鍋の状態が注文票の「茹で中 14秒」でしか分からない。
- 対応: 店内の見下ろし視点でも、各鍋の上に小さな円形タイマーを出す。食べごろになったら湯気が強くなり、音が鳴る。店内にいても鍋の様子で判断できるようにする。

### B8. 失敗も楽しく【P3】
- 具材を器の外に落とす（たまに）、スープを少しこぼして台を拭く、などの小さな失敗演出。品質への影響は小さく、笑える方向で。

## 5. 料理の見た目

### C1. スープ面の油玉がドット柄に見える【P1】
- 現状: `07-cooking-result.png` の麻辣スープで、ほぼ同じ大きさの丸い油玉が均等に散っている。
- 対応（`Visual/SoupVisuals.cs`・`TextureFactory.cs`）:

## 6. お客さんの様子

### D1. レジの会話で客の顔が見えない【P1】

- 現状: 客が「ピリ辛（辛さ1）」と数値で言い、注文欄の下にも「具材：…」と全文が出ている。
- 対応:
  - 序盤は今のまま、店舗レベルが上がると客の言い方が曖昧になる（「ちょっとだけ辛く」「しびれるやつ」「いつもより辛め」など）。言い方と辛さの対応表を `Core/CustomerVoice.cs` に追加し、テストする。
  - 注文欄の下の全文表示は、序盤（チュートリアル中）だけにする。以後は「もう一度聞く」ボタンで聞き直せるが、忍耐が少し減る。
- 完了条件: 言い回し→辛さの対応のテスト。チュートリアル中とそれ以降で表示が切り替わる PlayMode テスト。

### D3. 待っている間の感情の変化【P1】
- 現状: 待機は `Idle`・`Think` ポーズが中心で、忍耐は注文票の緑のバーだけ。
- 対応: 忍耐の残りに応じて段階的に動きを変える。
  - 70%以上: きょろきょろ、店内を眺める、スマホを見る
  - 40〜70%: 足をトントン、腕組み、時計を見る
  - 40%未満: ため息（頭上に小さな雲）、ちらちら厨房を見る
  - 帰るとき: 首を振って出ていく。ドアの音を強めに
- 頭上に小さな感情アイコン（汗・もやもや・ハート）を出す。

### D4. 料理を受け取ったとき・食べるとき【P1】
- 現状: `08b-eating-closeup.png` で、箸が顔の横で止まり、頭が器から離れたまま。すする動きがない。
- 対応:
  - 受け取ったら手を合わせる／目を輝かせる。写真好きの客タイプ（配信者など）はスマホで写真を撮る。
  - 食べるとき: 箸先が器→口へ動き、麺はすする（音つき）、ときどきれんげでスープを飲む。辛さが好みより高いと汗・顔が赤くなる・水を飲む。
  - 完食したら器を少し押して満足げに背もたれにもたれる。
- 完了条件: 食事中の動きの段階（つまむ→口へ→噛む）を時間で切り替える処理をテストする。スモークの `08b` を更新する。

### D5. 客タイプの見た目の差が小さい【P2】
- 対応: 客タイプごとの服装・持ち物（会社員はスーツと鞄、学生は制服とリュック、旅行者はキャリーケースと地図、ライダーはヘルメット、評論家はメモ帳）。`Core/Appearance.cs` に持ち物の項目を追加（保存形式に関わる場合は末尾追加）。

### D6. グループ・会話【P2】
- 団体客・カップル・親子が同じテーブルで会話する（吹き出しが交互に出る、うなずき合う）。
- 常連同士が店内で顔見知りとして挨拶する。

### D7. 店の外の行列と入店の迷い【P2】
- 混雑時は店の外に列ができる（歩道に並ぶ）。
- 通行人が店の前で立ち止まって中を覗き、評判や混み具合で入るか決める（入らずに去ることもある）。評判が上がると覗く人が増える、という形で成長を目に見えるようにする。

### D8. 退店とお見送り【P3】
- 満足した客は手を振る・会釈して帰る。常連は店主の名前を呼んで挨拶する。チップを置いたら机に小銭が残る（片付けで回収）。

- 店内: 客の話し声のざわめき（客数で大きく）、食器の音、すする音。
- BGM: 時間帯（昼・夕・夜）とラッシュで、テンポと楽器を変える。
- 街: 車・自転車のベル・鳥（朝）・虫（夏の夜）・雨音。
